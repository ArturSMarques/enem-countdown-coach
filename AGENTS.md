- Plan logic lives in src/lib/planner.ts (pure, tested); persisted state + actions in src/lib/store.ts (localStorage, no backend) — keeps scheduling testable and the app offline-first. The plan is rolling (HORIZON_DAYS ahead, extended on load) with phases (base, aprofundamento, revisão, semana final), spaced reviews and Sunday mock tests.
- ENEM dates come from src/lib/editions.ts: official editions (dates and exam-day rules from Inep editais) plus an estimate for years without an edital. The target edition follows today's date; never hard-code a year. When a new edital comes out, add it to OFFICIAL.
- The saved state is versioned (`version` inside the "reta-final-enem-v1" key). Any format change needs a step in migrate() and a test in src/test/state-migration.test.ts; users must never lose data.
- Keep YouTube parsing and launching in src/lib/youtube.ts and route external study links through ExternalResourceLink — one validation path, always a plain https link in a new tab (never intent:// or youtube:// schemes, which leave a blank tab or do nothing on phones; the OS opens the YouTube app by itself). This is a web app, not a Capacitor/Cordova package; add a native external-launch adapter only if a wrapper is introduced.
- Topic depth lives in src/lib/content/<area>.ts (TopicContent: resumo, base, intermediario, avancado, armadilhas, exercicios), shown at /conteudos/$topicId (file routes/conteudos_.$topicId.tsx, not nested). Accuracy first: anything uncertain goes in `aConfirmar`, never stated as fact.
- Topic priorities follow src/lib/incidence.ts (own classification of the official 2024–2026 exams, method in docs/incidencia-enem.md): alta ≥ 6 questions in the three exams, média 3–5, baixa ≤ 2. A test enforces this; update both together. The planner weights topics by that count.
- Daily questions: short ones in src/lib/questions.ts, ENEM-style ones (texts, tables, SVG figures from src/lib/figures.ts) in src/lib/questions-enem.ts, in-depth ones with an explanation for every alternative (`porQue`) in src/lib/questions-depth.ts. Both are append-only because ids are saved in localStorage. Every question has a level (facil/media/dificil); selection logic is pure in src/lib/quiz.ts. Answers by level per area (src/lib/mastery.ts) set a stage (base/regular/avancado) that the planner and the daily selection use.
- Build for Cloudflare inside Lovable and for a Node server (nitro preset node-server) when RENDER=true, gated in vite.config.ts — so the same repo publishes on Lovable and runs on Render with `node .output/server/index.mjs`.
- Personalized plan (state version 3): `Config` has `shifts` (manhã/tarde/noite), `hours` as a number (1,5 h from older versions stays valid), difficulty 1–10 (planner uses `0.6 + diff * 0.1`, equivalent to the old 1–5 scale doubled) and optional `goals` per area. Area weights are adjusted by goals and course weights only within 0.8×–1.3× (`areaFactors`), and no shift gets less than 25 min (`shiftsForDay`). Course weights live in src/lib/course-weights.ts and only with an official source, year and link; anything unconfirmed goes to docs/pesos-pendentes.md, never estimated.
- Topic mastery is computed, never self-marked: src/lib/topic-mastery.ts reads `state.attempts` (every answer: question, choice, hit, day, ms; part of state version 3, filled from `quiz` when missing) with the rules in src/lib/mastery-config.ts (levels Não iniciado → Dominado, hit rate weighted by level, last 30 days only, "Dominado" only for topics with ≥ 8 questions in the bank). The planner weights topics by that level (`LEVEL_W`, anchored on the old manual weights). `state.status` keeps the old manual marks but is no longer read; the self-reported "Registrar questões" form does not count for mastery.
- Question bank (phase 4): `Question` has optional `source` (banca, ano, etapa, número, official link), `uso` and `revisada`. Real exam questions show their origin and link, and their statement only when `uso: "liberada"` (`canShowContent`); official hosts per board live in src/lib/credits.ts (ITA and Fuvest have none until confirmed, so the test refuses their questions). New questions go to src/lib/questions-novas.ts with `revisada: false` and enter QUESTIONS only when flipped to true after review (students check, the teacher approves); regenerate docs/revisao-questoes-novas.md with `bun run revisao`. Every math answer must be computed, not guessed. Integrity tests: src/test/question-bank.test.ts.
- Desempenho (phase 5): pure logic in src/lib/performance.ts (PERFORMANCE_CONFIG: same 30-day window as mastery, 5 answers per area minimum). The pentagon (recharts radar via components/ui/chart.tsx) shows the weighted hit rate per area; Redação shows "sem dados" until essays are corrected. "Pendências a melhorar" replaces "Pontos fracos": topics with recent misses, with the topic tip, a trap from the content and, for in-depth questions, the error type of the chosen alternative (src/lib/error-types.ts: one letter per alternative, F/I/C/K/D, "." on the answer; the teacher may adjust; a test checks every code against the answer).
- Leagues and XP (phase 6, device only): rules in src/lib/league-config.ts ("moderado": leagues at 0/400/1,500/4,000/8,000 XP; answer 2 XP, hit +5/+10/+20 by level, block 10, streak +5 per day up to 35). XP is recomputed from attempts, finished blocks and studied days (src/lib/league.ts), so no new saved data. One league down only after 21 days without study, back on return. `pickQuestions` takes `league` as the ceiling of difficulty (Fundamentos easy only, Básico easy+medium, Intermediário up all) and, from Avançado, prioritizes released real questions; the area stage adjusts within that ceiling. Time per question is shown from Intermediário on, never as a penalty.
- Selected lessons (phase 7): src/lib/lessons.ts holds lessons chosen by the teacher per topic and level (base, intermediário, aprofundamento, resolução), with title and channel as credit and "Selecionada por <name as given, with title>". Never invent a video ID: IDs come only from a real YouTube Data API search (`bun run aulas:candidatas`, key in YOUTUBE_API_KEY / .env, run by the team) or a link pasted by the teacher. `bun run check:lessons` (oEmbed, no key) flags removed videos into docs/aulas-substituir.md; it is not part of the unit tests, which stay offline. Lessons open through ExternalResourceLink and never count toward mastery. How-to: docs/aulas.md.
- Study (phase 8): adaptive spaced review in src/lib/review.ts (REVIEW_STEPS 1/3/7/14/30 days per topic from `attempts`: a day all right moves one step, any miss goes back to 1 day); answered topics follow it in the plan (`adaptiveTopics` in buildPlan), never-answered ones keep REVIEW_GAPS. "Revisão de hoje" on the home page; a due topic's page turns the quick test into a 3-question review that can repeat old questions (`recordAnswers` appends attempts; `quiz` keeps the first answer). Mini-simulados at /simulado (src/lib/simulado.ts): one area, 10 or 20 questions, 3 min each, exam mode without feedback until delivery (QuestionCard `mode`), result by topic; answers go to attempts. AI essay correction is postponed until the privacy phase and the decision on parental consent.
